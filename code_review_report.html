Code Review Report

Đề tài: Nghiên cứu và xây dựng hệ thống Web Application Firewall sử dụng Machine Learning và kiến trúc Mixture of Experts để phát hiện tấn công ứng dụng web.

Nguyên tắc review: chỉ dựa trên source code đã đọc; phần chưa thấy trong code được ghi rõ.

1. Tổng quan đồ án

Project là một hệ thống kết hợp xử lý dữ liệu, huấn luyện mô hình, đánh giá mô hình và demo WAF runtime. Hệ thống nhận dữ liệu HTTP request, chuẩn hóa schema, trích xuất feature bảo mật, train mô hình Random Forest/MoE, sau đó deploy model vào FastAPI server để Nginx hỏi trước khi cho request vào backend.

Xử lý dữ liệuFeature extractionTraining MLEvaluationMoEFastAPI WAFNginx demo
Điểm mạnh: đồ án không chỉ train model offline mà có cả pipeline demo thực tế: Client → Nginx → WAF server → Backend.
Lưu ý: Không thấy README.md ở root project. Có nhiều entry point khác nhau, cần nói rõ script nào là pipeline chính khi báo cáo.

4. Review từng file code

4.1 features/extractor.py

  • Vai trò: file cốt lõi, chuyển request thành vector 32 feature.
  • Class chính: FeatureExtractor.
  • Luồng: lấy method/url/body/header → decode URL nhiều tầng → xác định query/body → tính keyword, entropy, header anomaly, URL penalty → trả vector.
  • Liên kết: mọi script train/evaluate/server đều dùng file này.
  • Điểm báo cáo: đây là cầu nối giữa HTTP text và ML numeric vector.
url_decoded, url_enc_depth = self._full_decode(url)
effective_payload = self._get_effective_payload(method, url, body)
injection_text = f"{url_decoded} {effective_payload}"

Giải thích: hệ thống không chỉ nhìn body mà còn nhìn URL đã decode, giúp phát hiện payload bị encode nhiều tầng.

4.2 config/keywords.py và features/helpers.py

  • keywords.py chứa danh sách keyword và trọng số.
  • helpers.py tính entropy, đếm keyword, điểm header bất thường, extension nguy hiểm, upload file độc hại.
  • Rủi ro: keyword substring có thể gây false positive; code đã giảm một phần bằng boundary regex cho SQLi.

4.3 baseline_train.py

  • Vai trò: train RandomForest baseline.
  • Hyperparameters: threshold 0.5, class weight {0:1,1:2}, 300 trees, max depth 30, test size 0.2.
  • Lỗi logic: code load 4 dataset nhưng gán merged = csic, nên thực tế chỉ train CSIC.
Cần sửa trước khi báo cáo kết quả baseline: đổi thành merged = csic + ecml + httpparam + biblio.

4.4 mfi_train.py

  • Vai trò: xử lý missing feature do HTTPParam/Biblio thiếu URL/header.
  • Chiến lược: baseline zeros, MFI-Mean, MFI-Class-Conditional.
  • Lỗi/rủi ro: MFI-Class-Conditional dùng y_test để impute test set, gây data leakage.
X_test_cc = apply_mfi_class_conditional(
    X_test, y_test, src_test, mean_class0, mean_class1)

Giải thích: khi deploy thật không biết nhãn trước, nên cách này chỉ nên xem là upper-bound/oracle nếu chưa sửa.

4.5 moe_train.py

  • Vai trò: MoE v1 rule-based gồm 2 expert.
  • Expert_Full: train CSIC+ECML.
  • Expert_Payload: train HTTPParam.
  • Router: có URL/header thật thì dùng full, ngược lại payload-only.
  • Predict: hard routing hoặc soft weight cố định.

4.6 moe_train_v2.py

  • Vai trò: MoE học thuật hơn, có expert RF/XGB/LGBM và gating Logistic/MLP/Sparse.
  • Expert factory: make_expert().
  • Gating: LogisticGating, MLPGating, SparseTopKGating.
  • MoE: MixtureOfExperts fit/predict.
  • Rủi ro: sample_weight chưa được truyền vào expert.fit() trong refit.
gate_w = self.gating.predict_weights(X)
expert_proba = np.column_stack([
    e.predict_proba(X)[:, 1] for e in self.experts
])
return (gate_w * expert_proba).sum(axis=1)

Giải thích: xác suất cuối cùng là tổng có trọng số giữa xác suất attack của các expert.

4.7 waf_server/app.py

  • Vai trò: FastAPI inference server.
  • Endpoint: /predict, /auth, /benchmark, /scan, /health.
  • Runtime: load model bằng pickle, extract feature, predict probability, trả verdict.
  • Rủi ro: pickle chỉ an toàn với model tin cậy; log có thể chứa cookie/authorization/payload.

4.8 test_datasets.py

  • Vai trò: đánh giá model trực tiếp, qua API hoặc qua Nginx.
  • Metric: Accuracy, F1-macro, AUC, TP/TN/FP/FN, precision/recall attack, latency.
  • Điểm báo cáo: chứng minh mô hình được đánh giá cả offline và trong pipeline deploy.

4.9 lab/nginx/waf.conf và lab/docker-compose.yml

  • Nginx: dùng auth_request /waf-check để hỏi WAF trước khi proxy backend.
  • Docker compose: dựng 3 service: nginx, waf, backend.
  • Lưu ý: config hiện fail-open khi WAF lỗi.

6. Giải thích mô hình Machine Learning

Random Forest

Khai báo trong baseline_train.py, model/trainer.py, mfi_train.py, moe_train.py, moe_train_v2.py. Input là ma trận feature; output là xác suất attack qua predict_proba. Tham số thường thấy: 300 cây, depth 30, class_weight để giảm bỏ lọt attack.

XGBoost / LightGBM

Trong moe_train_v2.py, import optional. Nếu thiếu thư viện thì fallback sang GradientBoostingClassifier. Vai trò là tạo expert đa dạng trong MoE.

Logistic Regression

Dùng làm gating trong LogisticGating. Đây là gate tuyến tính, dễ giải thích, học expert nào phù hợp hơn cho từng sample.

MLP

Dùng trong MLPGating và Sparse gating backbone. Có khả năng học quan hệ phi tuyến giữa feature và routing expert.

Metric trong code

  • Accuracy: tỷ lệ dự đoán đúng tổng thể.
  • F1-macro: trung bình F1 của normal và attack, phù hợp khi dữ liệu mất cân bằng.
  • AUC-ROC: đo khả năng phân tách theo xác suất.
  • Confusion matrix: TN/FP/FN/TP; đặc biệt quan trọng là FN/missed attacks.

  1. MoE v1 (moe_train.py): rule router chia request thành full hoặc payload-only, rồi dùng expert tương ứng.
  2. MoE v2 (moe_train_v2.py): nhiều expert RF/XGB/LGBM và gating network học trọng số expert.

9. Câu hỏi phản biện và trả lời ngắn

Câu hỏiTrả lời gợi ý
Vì sao chọn Random Forest?Dữ liệu sau extractor là dạng bảng; RF dễ train, chịu được feature phi tuyến, có class_weight và feature importance.
Vì sao cần MoE?Các nguồn dữ liệu khác nhau: request đầy đủ URL/header và request payload-only. MoE cho phép expert chuyên biệt và gate kết hợp expert phù hợp.
Gating network hoạt động thế nào?Gate nhận feature X, học dựa trên performance của expert, rồi xuất trọng số cho từng expert.
Một sample có thể dùng nhiều expert không?Có trong MoE v2: output cuối là tổng có trọng số giữa nhiều expert; Sparse Top-K chỉ giữ top K expert.
Vì sao cần MFI?HTTPParam/Biblio thiếu một số trường, khiến feature URL/header thiếu hoặc bằng 0. MFI thử bù bằng thống kê từ nguồn đầy đủ.
F1 quan trọng hơn Accuracy vì sao?Vì bài toán bảo mật quan tâm cả false positive và false negative; Accuracy cao vẫn có thể bỏ lọt attack nếu dữ liệu mất cân bằng.
Code phát hiện kiểu attack nào?SQLi, XSS, path traversal/LFI, command injection, PHP injection, probing/scanner, upload file nguy hiểm theo keyword/feature trong code.
Có phát hiện zero-day không?Chưa đủ dữ liệu để kết luận. Code chưa có đánh giá zero-day riêng.
Điểm yếu hiện tại?Baseline có lỗi merge, MFI có leakage, MoE weighted refit chưa hoàn chỉnh, docs feature count chưa đồng nhất, log có thể chứa dữ liệu nhạy cảm.
WAF lỗi thì hệ thống xử lý sao?Nginx config hiện fail-open: WAF lỗi thì request vẫn qua backend. Đây là trade-off availability/security.

11. Đoạn giải thích dùng trong báo cáo/thuyết trình

Trong hệ thống, dữ liệu HTTP request ban đầu được chuẩn hóa về cùng một cấu trúc gồm method, URL, payload, headers và nhãn. Do các bộ dữ liệu có mức độ đầy đủ khác nhau, ví dụ HTTPParam thiếu URL và header, hệ thống bổ sung các trường mặc định và lưu lại nguồn dữ liệu để đánh giá riêng theo từng dataset.

Sau khi chuẩn hóa, mỗi request được đưa vào module trích xuất đặc trưng. Module này phân tích query string, body, URL đã decode nhiều tầng và HTTP headers để tạo ra vector đặc trưng số. Các đặc trưng bao gồm độ dài payload, tỷ lệ ký tự đặc biệt, entropy, số lượng từ khóa SQL Injection, XSS, path traversal, command injection, dấu hiệu upload file nguy hiểm, điểm bất thường của header và các đặc trưng liên quan đến URL encoding.

Vector đặc trưng sau đó được dùng để huấn luyện các mô hình học máy. Baseline của hệ thống là Random Forest. Để xử lý sự khác biệt giữa các nguồn dữ liệu, đồ án thử nghiệm Missing Feature Imputation. Đối với kiến trúc Mixture of Experts, hệ thống xây dựng nhiều expert khác nhau, mỗi expert đưa ra xác suất request là tấn công, còn gating network sinh trọng số cho từng expert. Xác suất cuối cùng được tính bằng tổng có trọng số giữa xác suất của các expert.

Trong phần demo triển khai, model đã huấn luyện được lưu thành file .pkl và được FastAPI WAF server load khi khởi động. Nginx sử dụng auth_request để gửi subrequest đến WAF server trước khi chuyển request đến backend. Nếu WAF trả về HTTP 403, Nginx chặn request; nếu trả về HTTP 200, request được proxy đến backend.

Cần nhớ khi bị hỏi: nói trung thực các hạn chế trong code: baseline merge bug, MFI leakage, MoE refit chưa weighted hoàn chỉnh, fail-open, logging dữ liệu nhạy cảm.
